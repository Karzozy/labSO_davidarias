Taller 1 - llamadas del sistema

Se realizaron dos programas donde el primer programa cuenta con un codigo de salida diferente a cero, en este caso le coloque 7 (exit(7)) lo que se comprueba con la linea echo $? presente en la guia, tambien, imprime el identificador de proceso y el de su proceso padre acompanado de un mensaje en la salida estandar usando write, es decir, bytes mandados directos al kernel sin pasos intermedios como lo hace printf que acumula en buffer antes de llegar a pantalla al no tener saltos de linea ni contar con fflush() que fuerce a que el contenido del buffer se envie al kernel (esto con fines de la guia) siendo esta la razon por la que en el segundo programa se imprime primero el texto con write que con printf, profundizando en el segundo programa el cual imprime el mismo texto dos veces donde nos permite observar que el orden en el que aparece el texto en pantalla no depende del orden en el que se llama a las funciones en el codigo, sino de cuando cada una transfiere los datos al kernel.
Como write es una llamada del sistema y por lo mencionado anteriormente, el texto de este llamado aparecio primero que el mandado mediante la funcion de biblioteca printf. Para entender un poco mas la diferencia entre esta llamada del sistema y esta funcion de biblioteca podemos ver lo que retorna cada una en el apartado de return values dentro de "man 2 write" y "man 3 printf" donde el tipo de dato que maneja cada una es diferente, write retorna un ssize_t que representa la cantidad exacta de bytes fisicos escritos directamente, mientras que printf devuelve un entero que cuenta los caracteres logicos y los envia al bufer de la libreria estandar. Ademas el manejo de errores se hace de manera diferente, write devuelve un -1 y delega el problema a la variable errno, mientras printf retorna cualquier valor negativo para indicar una falla en la salida. 
Pasando por fuera del caso ideal en prog1, primero se valida el retorno de snprintf al armar el mensaje, y luego se guarda el retorno de write en una variable para evaluarlo en dos escenarios: si devuelve -1, se informa la causa con perror y el programa termina con exit(1) y si devuelve un valor valido pero menor a la cantidad de bytes solicitada, tambien se trata como un error, ya que significa que no todo el mensaje llego al kernel, solo si write devolvio exactamente lo esperado, el programa continua hasta terminar con el codigo de salida elegido (exit(7)). En prog2 se aplica la misma logica de verificacion sobre el write utilizado para el segundo mensaje donde tuve problemas con algunos casteos en cuestion de tipos con signos con strlen y write.
